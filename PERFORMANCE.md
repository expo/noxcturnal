# Performance notes

Performance claims in this project are machine-local regression indicators. They are not
portable throughput guarantees. Run `pnpm benchmark` for the library stress cases and run
`npm run bench` in `../metro-transform-spike` for the transform-worker comparison.

## Workloads

The standalone suite uses a 2,000-statement, 82.7 KiB module. It deliberately separates
costs that tend to be combined in a Babel plugin stack:

- a narrow Identifier visitor;
- twelve plugins receiving the same route;
- seven plugins with disjoint routes;
- an edit for every Identifier;
- a catch-all visitor over every node;
- binding and parent lookup for every Identifier;
- three explicit render/reparse phases;
- declared structural children, which require a retained native node index.

The Metro spike remains the representative mixed transform. It parses and builds semantics,
checks global bindings, rewrites defines and static dependencies, inserts a strict directive,
wraps scripts, and emits source maps over 500 synthetic files (847.9 KiB).

## July 2026 results

On the development macOS arm64 machine, representative warm means were:

| Workload | Time |
| --- | ---: |
| Narrow Identifier visitor | 1.68 ms |
| Dense Identifier edits | 2.29 ms |
| Twelve-plugin same-route fan-out | 3.30 ms |
| Catch-all streaming visitor | 4.31 ms |
| Seven-plugin disjoint dispatch | 4.51 ms |
| Three render/reparse phases | 5.65 ms |
| Declared Program children | 5.90 ms |
| Scope and ancestry lookup per Identifier | 6.09 ms |

The Metro spike completed in 20.3 ms median versus 213.6 ms for Babel and 77.2 ms for
Oxc-walker plus MagicString: 10.55x and 3.81x respectively. All implementations observed
8,500 dependencies and passed the output parse/checksum checks.

## Findings and changes

Phase dispatch previously tested every event against every plugin. A phase-level route cache
now sends an event only to plugins with matching handlers while retaining plugin ordering and
reverse exit ordering. The seven-plugin disjoint workload fell from 8.44 ms to 4.49 ms (47%).
The one-plugin path bypasses this cache.

Scope helpers previously issued and scanned a new Identifier query for every distinct binding
name. A realistic `path.scope.hasBinding(path.node.name)` loop exhausted the default 64-batch
limit; with a raised limit it took roughly 52 ms warm. Sessions now build binding and global
indexes once from semantic Identifier facts. The workload completes under the default budget
in about 6.09 ms.

The remaining broad and structural costs have different causes. Catch-all visitors necessarily
transfer and replay every selected node. Structural child access uses the retained-session path,
whose owned records permit safe follow-up calls after Oxc's arena and borrowed AST have gone out
of scope. Replacing it with a self-referential borrowed AST session could reduce allocation, but
would materially increase native safety and lifetime complexity. The measured cost does not yet
justify that trade. A future targeted alternative would encode declared parent/child families
directly during the initial traversal without retaining every owned event.

Multiple phases intentionally pay for multiple parse/semantic/traversal passes because a later
phase observes code generated by earlier phases. Independent plugins should stay in one phase;
only edit-dependent transforms should introduce a phase boundary.

## Regression guidance

Optimize against the cause identified by a workload, not its fixture text. Preserve these
invariants:

- narrow visitors must not allocate a broad retained index;
- plugin count should not multiply dispatch work for unrelated routes;
- repeated scope lookup must not trigger repeated FFI batches;
- edit density should primarily scale with actual edit count;
- phase count may scale parse work only when the caller asks for edit visibility boundaries.
